# ELK Stack with ElastiFlow for NetFlow & sFlow Monitoring

Distributed ELK deployment using ElastiFlow for network flow collection.

**SECURITY WARNING:** See [SECURITY.md](SECURITY.md) - Change all default passwords before use!

## Architecture

```
Frontend Server (<FRONTEND_IP>)
├── Elasticsearch (master + data + ingest)
├── Elasticsearch-2 (master + data + ingest)
└── Kibana (port 5601)

Backend N1 - NetFlow Collector (<COLLECTOR_1_IP>)
├── ElastiFlow 7.21.0 (UDP 2050)
├── Manages ES index templates ✓
└── Receives from: NetFlow exporters (routers, switches)

Backend N2 - sFlow Collector (<COLLECTOR_2_IP>)
├── ElastiFlow 7.21.0 (UDP 2050, 6343)
├── Index templates DISABLED ✓
└── Receives from: sFlow exporters (switches)

Network Devices
├── Router/Switch → Backend N1:2050 (NetFlow v9)
└── Switches → Backend N2:6343 (sFlow v5)
```

## Prerequisites

- Docker & Docker Compose installed on all servers
- Network connectivity between collectors and Elasticsearch
- TLS certificates (auto-generated by deploy.sh)

## Quick Start

```bash
# 1. Clone the repository
git clone https://github.com/your-org/custom-elk-stack.git
cd custom-elk-stack

# 2. Generate configuration
./deploy.sh --generate

# 3. Edit deploy.conf with your settings
nano deploy.conf
# - Set ELASTIC_PASSWORD and KIBANA_PASSWORD
# - Set FRONTEND_IP to your frontend server IP
# - Set ELASTICSEARCH_HOST
# - Configure ElastiFlow collectors with their IPs

# 4. Deploy
./deploy.sh
```

## Deployment Options

```bash
./deploy.sh -h              # Show help
./deploy.sh -g              # Generate config file
./deploy.sh -c              # Check prerequisites only
./deploy.sh -f              # Deploy frontend only
./deploy.sh -e              # Deploy ElastiFlow collectors
./deploy.sh -i              # Import dashboards only
./deploy.sh -v              # Verify deployment
```

## ElastiFlow Collector Configuration

### Primary Collector (N1) - Manages Templates

Only ONE collector should have `EF_OUTPUT_ELASTICSEARCH_INDEX_TEMPLATE_ENABLE: "true"`:

```yaml
# configs/elastiflow/docker-compose-n1.yml
environment:
  EF_FLOW_SERVER_UDP_PORT: "2050"
  EF_OUTPUT_ELASTICSEARCH_INDEX_TEMPLATE_ENABLE: "true"  # PRIMARY
```

### Secondary Collectors (N2+) - Templates Disabled

All other collectors must have templates disabled to avoid bootstrap conflicts:

```yaml
# configs/elastiflow/docker-compose-n2.yml
environment:
  EF_FLOW_SERVER_UDP_PORT: "2050,6343"
  EF_OUTPUT_ELASTICSEARCH_INDEX_TEMPLATE_ENABLE: "false"  # SECONDARY
```

## Network Device Configuration

### Cisco Nexus (sFlow v5)

```cisco
feature sflow
sflow collector-ip <COLLECTOR_IP> vrf default
sflow collector-port 6343
sflow agent-ip <switch-ip>
sflow sampling-rate 4096
sflow max-sampled-size 128
sflow counter-poll-interval 20
sflow max-datagram-size 1400

# Configure interfaces to monitor
sflow data-source interface port-channel1
sflow data-source interface Ethernet1/1
```

### Juniper (NetFlow v9)

```juniper
set services flow-monitoring version 9
set forwarding-options sampling input rate 4096
set forwarding-options sampling family inet output flow-server <COLLECTOR_IP> port 2050
set forwarding-options sampling family inet output flow-server <COLLECTOR_IP> version 9
```

## Troubleshooting

### Collector Shows "unhealthy"

```bash
# Check logs
docker logs flow-collector --tail 50

# Common issue: Index template conflict
# Solution: Only ONE collector should have INDEX_TEMPLATE_ENABLE: true
```

### No Data from Devices

```bash
# Check if collector is listening
ss -uln | grep -E "(2050|6343)"

# Check firewall
sudo ufw status

# Query Elasticsearch for data
curl -k -u elastic:password https://<ES_IP>:9200/elastiflow-*/_search?size=1
```

### Cluster Health Issues

```bash
# Check cluster status
curl -k -u elastic:password https://<ES_IP>:9200/_cluster/health

# Check nodes
curl -k -u elastic:password https://<ES_IP>:9200/_cat/nodes?v

# Check indices
curl -k -u elastic:password https://<ES_IP>:9200/_cat/indices?v
```

## ILM Policy

Default: Hot → Warm → Delete after 3 days. Customize in `configs/elastiflow/ilm-policy.json`.
